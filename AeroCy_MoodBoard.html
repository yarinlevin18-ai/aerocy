06 · WorkflowHow we'll build this together

No design tool to learn. No code to write. You drive the design with words, I write the code. The loop below is what every session looks like.

01

I write a first draft

I create a single file: AeroCy/index.html. Self-contained — HTML, CSS, and any animation all in one file. Uses the locked-in palette (section 03) and fonts (section 04) as CSS variables, so changing a color later means swapping one value.

02

You preview by double-clicking

Open your AeroCy folder, double-click index.html. It opens in your default browser. That's your live preview — no server, no setup. Refresh the page after each change I make.

03

You tell me what to change — in plain words

You don't need to know code or design terminology. Examples that work:

  • "The hero feels too dark, brighten it"
  • "Make the headline bigger"
  • "Add a stats section below the hero with these numbers: 1000+ rules, 24/7 SOC, 3 decades AVSEC"
  • "Remove the testimonials section"
  • "I want a red/blue split like Wiz uses"
04

I edit the file, you refresh

I make the changes, the file updates in your folder instantly. You refresh the browser tab (F5 or Ctrl+R). See the change. Repeat.

05

Drop in assets when you want them

Find an aviation photo on Unsplash? Download it into your AeroCy folder, tell me the filename, I'll wire it into the right place. Same for icons, logos (when you have them), or any other image.

06

When it's good, we deploy

You make a free account at vercel.com. I'll walk you through dragging the AeroCy folder onto their dashboard — it gives you a live URL like aerocy.vercel.app in under a minute. When you buy the aerocy.io domain, we point it at Vercel. Done.

07

What you'll never have to do

  • Install Node.js, npm, or any developer tools
  • Open a terminal / command line
  • Learn HTML, CSS, or JavaScript
  • Use git or any version control
  • Pay for design software
One caveat: the most ambitious motion from Reventador (full scroll-assembled hero, 3D scenes) is technically possible in plain HTML/CSS/JS but takes more iteration than a no-code tool. We'll start simple — a clean, modern, animated landing — and add complexity only where it earns its keep.

07 · BlockersWhat still needs to be decided before final designs

From the PRD's Open Questions — these don't block starting the build with placeholders, but they block final sign-off.

  • Logo files from client (PNG / SVG transparent)
  • Final copy ownership (client vs build team)
  • Aviation imagery licensing — Unsplash for mockups, real licensed images for production
  • Hebrew version yes/no (affects type spec)
